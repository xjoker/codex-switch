# Working on codex-switch

Follow [CONTRIBUTING.md](CONTRIBUTING.md) for development and verification, [the release guide](docs/RELEASE.md) for tags and publishing, and [SECURITY.md](SECURITY.md) for security reports.

- For an Issue with several requests, state the outcome of each before closing it. Say what already works, what alternative covers the request, and what remains out of scope. Link the command, documentation, or merged change that supports each claim.
- When a fix ships, name the release channel, version, and verification evidence. Track delivery to the stable channel separately when its users are still affected.
- Use synthetic credentials and profiles in public examples and test fixtures. Route vulnerability reports through the private GitHub reporting link.
